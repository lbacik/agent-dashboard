## Review findings (both axes completed)

Standards axis: no hard violations (gateway-only argv, framework-free view
models, synthetic fixtures, TestClient fragments, DESIGN.md tokens all
comply). Judgement-only smells: long submit handler, repeated
refused/submitted/outcome dict shapes, retry/status hidden-field duplication.

Spec axis: one substantive finding — the **busy pre-check is missing**.
Spec 6.3 orders submit as "… → target binding (409) → the per-instance
busy check (409: 'Another command…') → the `submitted` entry → …" and says
"The busy check is the gateway's `ControlBusyError`, so it is decided
atomically when the exec starts", treating a post-`submitted` busy as the
race fallback. The current code never consults
`gateway.control_in_flight()` (exists at `gateway.py:1330`) before writing
`submitted`, so every busy submit leaves a `submitted`-without-exec pair
the spec's normal path would not create. Everything else matched
(refusal reasons, card bodies/tones, 503 wording, `retry`, write order).
